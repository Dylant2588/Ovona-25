# Recipe library operations

Deployment state: migration `20261012_recipe_library.sql` is prepared locally, not deployed by this change. Apply it using an authorized Supabase SQL administration connection. Existing recipes remain drafts; generation requires enough approved recipes for all requested slots.

Run from `frontend-new`:

1. `node scripts/export-recipe-library.cjs recipes.pending.json` exports the whole internal catalogue deterministically. Missing methods and estimated nutrition remain review work, never invented certification.
2. `node scripts/import-recipe-library.cjs recipes.pending.json` is a dry run. Add `--apply` with administrator environment variables to insert pending drafts. Duplicate ID/version rows are left untouched, including approved records.
3. Review an individual JSON record manually: verify provenance and usage rights, measured batch ingredient quantities/units, ingredient identity, supplier labels and possible cross-contact, method, servings, timing, nutrition calculation source, dietary flags and image rights. `ingredients.amount` describes the whole batch; `macros` describes **one serving**. Planner base ingredients divide batch quantities by `servings` and scale that serving once.
4. Every ingredient must match an exact entry in `taxonomy.ts`; composite/brand ingredients lacking an entry cannot pass. Add registry entries only after evidence review. Empty allergen lists mean reviewed absence of listed allergens, never absence of all possible allergens. Include supplier `mayContain` warnings. The taxonomy conservatively covers the [14 UK regulated allergen groups](https://www.food.gov.uk/business-guidance/allergen-guidance-for-food-businesses). [Recipe and ingredient changes require current allergen information](https://www.food.gov.uk/business-guidance/allergen-information-for-non-prepacked-foods-best-practice-voluntary-information). Unknown user allergies block approval; taxonomy checks are not an allergy guarantee or a substitute for supplier/cross-contact evidence.
5. Set ingredient `reviewed`, source and nutrition `reviewed` only after checking evidence. Set `review.status=approved`, `review.reviewedBy` to the accountable reviewer and `review.reviewedAt` to an ISO timestamp. `node scripts/review-recipe-library.cjs recipe.reviewed.json` checks evidence without writes; `--apply` records the administrator-reviewed record. The tool does not populate review evidence or approve drafts automatically.

Use `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` only in the administrator environment, never browser code or exported JSON. The migration grants authenticated clients read access to approved records and no write privileges. Approved versions are immutable in the workflow; create a new version for recipe/source/substitution updates. Keep older reviewed versions available for saved-plan validation.

Policies: mandatory allergies, dietary restrictions and dislikes never relax. Unrecognized dietary modes fail closed. Low-carb uses a 30g carbohydrate per-final-meal ceiling and high-protein a 20g protein minimum; these are explicit product rules rather than medical personalization. Prep limits also apply. A meal-out slot and external/AI recipe sourcing are future work.
