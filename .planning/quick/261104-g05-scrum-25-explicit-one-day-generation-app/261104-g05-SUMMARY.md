# SCRUM-25: Explicit one-day planning and safe saved revisions

The existing planner and recipe approval now support a complete one-day scope, while saved day/week plans use isolated complete immutable revisions and preserve prior plans on insert failure.

## Accomplishments

- `plan-scope.ts` validates scope/date, derives daily versus weekly anchors and owner/scope/date cache keys. Unknown scope and invalid calendar dates reject.
- The existing scheduler, portion budgets, unavoidable-ingredient lower bound, final validator and replacement validator accept a scope parameter, defaulting to week. No parallel scheduler or dietary validator was introduced.
- Generation materializes the requested one or seven days, uses matching rotation scope and performs existing final recipe/dietary/nutrition approval.
- State save approves first and inserts all rows under a new revision ID in one operation. No delete occurs. Weekly summary and rotation writes are best effort after the commit; daily saves never overwrite weekly summaries.
- State and shopping reads share paginated owner/anchor revision selection, with exact count, dates, unique identities and consistent metadata. Incomplete latest groups cannot mix or shadow a previous complete group. Legacy missing-scope rows are weekly only.
- Daily shopping and swap/day regeneration preserve scope and the original date. Recipe ingredient arithmetic remains unchanged.
- The orchestrator owns the daily UI/cache/scope-control portion and its isolated commit and browser checks.

## Deviations and risks

- The pre-existing state route's destructive delete-before-insert and post-commit false failure were fixed because they directly violated this ticket's preservation criteria.
- No database schema/dependencies were changed. If an environment has constraints incompatible with append-only revisions, insertion fails without deleting the prior plan; no destructive fallback exists.
- Saved GET remains explicitly `approval: unchecked`; it does not falsely label old evidence freshly approved. Current shopping still requires fresh server recipe/dietary approval.
- Append-only revisions accumulate history; lifecycle/retention is deferred rather than deleting active data during a save.
- Catalogue coverage is a separate SCRUM-26 concern. No reviewed recipes or live preferences were edited in this ticket.
- No deployment or merge. Earlier unrelated dirty shopping department/recipe-source UI changes remain preserved outside scoped commits.
