<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source/importer → recipe library | Untrusted imported records seek to become trusted user-facing recipes |
| user/client → rotation history | User-scoped accepted/eaten events must not expose another user's history |
| price provider → retailer observations | External price data can be incomplete, stale, or falsely attributed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | T/E | recipe imports and review status | mitigate | Require complete evidence and reviewer attribution; service-role-only review writes; immutable approved versions. |
| T-08-02 | I/T | user_meal_history | mitigate | RLS policy keyed to `auth.uid() = user_id`, least-privilege grants, and local RLS tests. |
| T-08-03 | S/T | retailer_price_observations | mitigate | Require operator-feed adapter version, retailer identifier, source reference, provenance state, observed/import timestamps; never scrape at runtime or grant client mutations. |
| T-08-04 | R | recipe review audit | mitigate | Persist import hash, actor, and timestamp in append-only audit metadata. |
</threat_model>
