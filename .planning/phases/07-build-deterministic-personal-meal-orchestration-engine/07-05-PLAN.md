<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| browser → route | Profile, plan, day, slot, and week date are untrusted request fields. |
| route → Supabase | Plan/history/list operations must be strictly authenticated and user-scoped. |
| adapter → UI | Only validated, verified deterministic results may be presented as an accepted plan. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-07-01 | T/D | weekly/swap request normalization | mitigate | Route passes server profile/context into normalizer; invalid numeric/date/slot ranges get 400/422. |
| T-07-02 | T | generated/swap plan | mitigate | Route accepts only pure-core validated results; hard allergy/diet violation and unverified candidate admission are blocking. |
| T-07-03 | E/R | plan_history and shopping persistence | mitigate | Resolve user with `resolveRequestAuth`; apply `eq('user_id', user.id)` on every read/write/delete and never trust payload user IDs. |
| T-07-04 | T | generation adapter boundary | mitigate | No LLM/unverified candidate response is persisted or shown as validated; structured insufficiency is returned instead. |
</threat_model>
